# Security Policy

BreachIn is currently an early-stage open-source prototype. Its security processes and supported versions may change as the project develops.

## Supported Versions

Only the latest version of the code on the default branch is currently supported with security updates.

## Reporting a Vulnerability

Please do not disclose suspected vulnerabilities publicly through GitHub Issues, discussions, pull requests, or other public channels.

If GitHub Private Vulnerability Reporting is enabled for this repository, use it to submit the report privately. If it is not enabled, contact the maintainers through an appropriate private channel available on their GitHub profiles. Do not include sensitive details in a public message.

## What to Include in a Report

Please provide:

- A clear description of the vulnerability and its potential impact
- The affected page, component, or code path
- Steps needed to reproduce the issue
- Any relevant proof-of-concept material, logs, or screenshots
- Suggested mitigations, if available

Remove or redact secrets, credentials, and personal information before submitting a report.

## Responsible Disclosure

Allow the maintainers reasonable time to investigate and address a reported vulnerability before publishing details. Please avoid accessing, changing, retaining, or sharing data that does not belong to you, and avoid actions that could disrupt the service or other users.

## Security Scope

The current scope covers the BreachIn application code and dependencies maintained in this repository. Third-party platforms, services, and infrastructure not controlled by the project are outside its scope.

Secrets, API keys, credentials, CV data, and personal information must never be committed to this repository. Use safe local configuration and development data, and review changes carefully before committing them.
